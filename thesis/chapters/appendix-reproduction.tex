\chapter{Reproducing the Results}\label{app:reproduction}
% The commands and scripts that regenerate every number in Chapter~\ref{chap:evaluation}.

This appendix lists what is needed to regenerate the tables of \Cref{chap:evaluation}. All commands are in the directories
\texttt{scripts} and \texttt{graal-native} of the tool's repository; the builder is the Graal fork, which the repository contains as a submodule.

\section{The Tables from One Commit}

The script \texttt{reproduce.sh} produces the tables of \Cref{sec:eval-gain,sec:eval-cost} in one run. It refuses to start unless
the tool and the fork are exactly a commit (no changed tracked files, no untracked files) and the builder is not older than the
fork's sources. With \texttt{ALLOW\_DIRTY=1} it runs for testing and marks the results \texttt{NOT-REPRODUCIBLE}. The chapter
measures no model of concurrency, which \texttt{THREAD\_ESCAPE=off} switches off in the builder. The procedure of the run of
2 November, on a machine where nothing else runs, was:

\begin{lstlisting}[language=bash]
# on the development machine, from clean, committed checkouts of the tool and of the fork:
scripts/server/sync-pontos.sh      # copies both trees to the server and stamps them with their commits

# on the server:
export JAVA_HOME=$HOME/.mx/jdks/labsjdk-ce-latest-jvmci-25.4-b23_amd64
export PATH=$JAVA_HOME/bin:$HOME/mx:$HOME/.local/bin:$PATH
cd ~/graal/substratevm && mx build # the builder must be newer than the sources
THREAD_ESCAPE=off ~/explicit-effects/scripts/evaluation/reproduce.sh          # loads, time, ceiling, cost
THREAD_ESCAPE=off ~/explicit-effects/scripts/evaluation/reproduce.sh control  # control flow and loops
\end{lstlisting}

In \texttt{graal-native}, the results are written to a directory of \texttt{out/reproduction/}, named by the UTC time, the
commit, and \texttt{no-thread-escape}: \texttt{provenance.txt} (which code), one file per stage, and \texttt{SUMMARY.txt}.
\Cref{tab:app-stages} lists the stages. The first four took 55 minutes on 2 November.
